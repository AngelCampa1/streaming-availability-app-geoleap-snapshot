## Prioritized Findings

### P0: Homepage client-side rendering (FIXED)

**File:** `frontend/src/app/page.tsx:1`
**Impact:** All homepage content (H1, hero, features, sections, HowTo schema) invisible to crawlers that don't execute JavaScript.

**Evidence:** `page.tsx` had `'use client'` directive. The metadata (title, description, OG tags) and org/website schemas in `layout.tsx` ARE server-rendered. But the page body was all client-only: H1 "Find Where to Watch", features, explore section, RelatedLinks, HowTo JSON-LD.

When Googlebot fetches `https://geoleap.app/` without JS execution:
- Gets: title, meta tags, org schema ✓
- Missing: H1, hero text, features list, explore links, HowTo schema ✗

**Fix applied:** Refactored `page.tsx` to a server component. Extracted interactive parts into three small client components:
- `HomeSearchInput`: search form with useState + useRouter
- `HomeCTAButtons`: hero CTA with useAuth + useABTest
- `BottomCTAButtons`: bottom CTA with useAuth

All static sections now server-rendered in initial HTML.

### P0: Cloudflare Bot Fight Mode blocking AI crawlers (ACTION REQUIRED)

**Location:** Cloudflare Dashboard → Security → Bots
**Impact:** GPTBot, ClaudeBot, Google-Extended, Amazonbot, Applebot-Extended are being blocked by Cloudflare's Bot Fight Mode BEFORE our `robots.ts` Allow rules take effect.

**Evidence from live robots.txt:**
```
# BEGIN Cloudflare Managed content
User-agent: ClaudeBot
Disallow: /
User-agent: GPTBot
Disallow: /
User-agent: Google-Extended
Disallow: /
# END Cloudflare Managed Content

# Our rules (appear after Cloudflare block):
User-Agent: ClaudeBot
Allow: /
...
```

Per RFC 9309, when multiple groups exist for the same user-agent, rules are merged and Allow takes precedence over Disallow for equal-length paths. Google's crawler follows this and will crawl. However, other AI crawlers (Perplexity, Claude) may use the first-match-wins interpretation, effectively being blocked.

**Fix required (not code, Cloudflare dashboard):**
1. Cloudflare Dashboard → Security → Bots
2. Disable "Block AI Scrapers" OR configure exceptions for your domain
3. Alternatively, switch robots.txt management entirely to the Next.js `robots.ts` (stop Cloudflare injection)

The code in `robots.ts` is correct and complete. The issue is purely Cloudflare configuration.

### P1: Author E-E-A-T: Organization-only author (PARTIALLY FIXED)

**File:** `frontend/src/lib/seo/schema-markup.ts:682`
**Impact:** Article and guide schemas use bare `author: { '@type': 'Organization', name: 'GeoLeap' }` without @id linkage to the Organization entity or sameAs signals. Google's E-E-A-T evaluation prefers named human authors for YMYL-adjacent content.

**Fix applied:** Updated `generateArticleSchema` and `generateStreamingGuideSchema` to use a richer author object with `@id` linking back to the Organization entity and `sameAs` social profile URLs.

**Recommended follow-up:** Add a named `Person` schema for the editor/author once there is a real named contributor. This requires a real person. Do not fabricate.

### P2: Speakable CSS selectors

**File:** `frontend/src/lib/seo/schema-markup.ts:611-613`

Speakable selectors in use across schemas:
- `.bluf-summary`: used in platform, country, genre, sports, compare schemas
- `.faq-answer`: used in WebPage and guide schemas
- `.tldr-summary`: used in guide schema
